# EAF v2.0 — Engagement Authority Framework

**Status:** Built — v2.0 (Reconciliation with ICC-8, IMP, AWOF, AICA-5, CEF, HOF/HIS-12, and DEP)  
**Type:** Trust Architecture Instrument  
**Parent Stack:** 19 Integrated Primitive Layer  
**Version:** 2.0 — Supersedes EAF v1.0

---

## PREAMBLE

The Engagement Authority Framework (EAF) defines the trust conditions under which client engagements are initiated, deepened, and concluded. It answers: *What is the AI-native operating architecture permitted to ask, infer, store, act upon, and retain at each stage of the client relationship?*

EAF is the trust architecture through which 19 Integrated's operating system is permitted to engage with the world. It defines the constitutional boundary between what the institution may do and what it may not — calibrated to the depth of the client relationship at any given moment.

**The core insight:** Trust is not binary. It is a spectrum of five tiers, each with defined permissions, storage limits, inference boundaries, and HAN conditions. EAF operationalizes the principle that trust is earned sequentially and can be lost immediately.

---

## SECTION 1: PURPOSE AND SCOPE

### Purpose

EAF ensures that:

1. **Trust is tiered** — Five trust tiers define what the AI operating architecture may do  
2. **Permissions are bounded** — Each tier has explicit permissions, storage limits, and inference boundaries  
3. **Trust is earned sequentially** — No skipping tiers; elevation requires completion of current tier conditions  
4. **Trust can be lost immediately** — Tier descent is immediate upon condition violation  
5. **HAN intervention is triggered** — HAN triggers are defined per tier and condition

### Scope

| In Scope | Out of Scope |
| :---- | :---- |
| Trust tier architecture (Tiers 1-5) | Client onboarding checklists |
| Permissions per tier | Terms of service documents |
| Storage and inference boundaries | Data privacy policies (informs but does not define) |
| HAN trigger conditions | Commercial terms or pricing |
| Tier elevation and descent | Client relationship management beyond trust |

### Governing Relationships

| Instrument | Relationship to EAF |
| :---- | :---- |
| **ICC-8** | Constitutional ceiling — EAF may not permit what ICC-8 prohibits |
| **IMP** | Governed by EAF — stores only what EAF permits |
| **AWOF** | Action layer — AI workforce operates within EAF-defined authority boundaries |
| **AICA-5** | AI accountability — EAF trust tiers map to AICA-5 accountability levels |
| **CEF** | Engagement layer — CEF engagement phases correspond to EAF trust tier transitions |
| **HOF/HIS-12** | Human authority layer — EAF HAN triggers activate HOF-defined authority nodes |
| **DEP** | Doctrine evolution — EAF amendments require DEP process |

## SECTION 2: FOUNDATIONAL PRINCIPLES

| \# | Principle | Description |
| :---- | :---- | :---- |
| **P1** | **Minimum Necessary Engagement** | At every trust tier, the AI operating architecture engages with the minimum client information necessary to fulfill the permitted function at that tier. |
| **P2** | **Consent Precedence** | Client consent governs what may be stored and inferred, subject to EAF tier constraints. Consent does not expand permissions beyond the active trust tier. |
| **P3** | **HAN as Governance Trigger** | Human Accountability Node intervention is not a quality check. It is a governance event triggered by EAF rules. |
| **P4** | **Trust is Earned Sequentially** | No engagement may skip trust tiers. Tier elevation requires completion of all conditions defined for the current tier. |
| **P5** | **Irrevocability of Tier Descent** | If conditions for a trust tier are violated or withdrawn, the relationship descends to the highest tier whose conditions remain intact. Tier descent is immediate. |
| **P6** | **EAF Supremacy Over Commercial Logic** | No commercial consideration — contract terms, client request, revenue pressure, relationship history — overrides EAF. EAF violations are constitutional violations under ICC-8. |
