# ERDP v2.0 — External Reporting & Disclosure Protocol

**Status:** Built — v2.0 (Reconciliation with ICC-8, CEN-1 to CEN-7, IMP, AICA-5, ILTP, CGF, HAN/HOF, and DEP)  
**Type:** Reporting & Disclosure Instrument  
**Parent Stack:** 19 Integrated Operational Infrastructure  
**Version:** 2.0 — Supersedes ERDP v1.0

---

## PREAMBLE

The External Reporting & Disclosure Protocol (ERDP) governs all external reporting and disclosure obligations of 19 Integrated and its three SPV entities. It answers: *What is disclosed, to whom, on what schedule, and under what conditions?*

ERDP operationalizes the external legibility requirement under I8 of ICC-8 and the Contestation Interface Standard (CEN-1 through CEN-7) across all entities. It defines what is disclosed, to whom, on what schedule, and under what conditions. It ensures that 19 Integrated's institutional actions are externally legible, auditable, and contestable.

**The core insight:** A governance structure that cannot be seen from outside is not governance—it is a private arrangement. ERDP transforms institutional governance from an internal practice into an externally verifiable system, satisfying the constitutional requirement that all material institutional actions be mappable to an external interpretation path.

## SECTION 1: PURPOSE AND SCOPE

### Purpose

ERDP ensures that:

1. **External legibility is maintained** — I8 External Legibility is operationalized through defined disclosure  
2. **Disclosure is tiered** — Four disclosure tiers define what is disclosed to whom  
3. **Reporting is periodic** — Annual Institutional Report (AIR) and Quarterly Operational Update (QOU) provide regular disclosure  
4. **Event-triggered reporting is defined** — Material events trigger disclosure within defined windows  
5. **Confidentiality is protected** — I6 Transparency Gradient is respected  
6. **Contestation is enabled** — CEN-1 to CEN-7 provide external contestation pathways

### Scope

| In Scope | Out of Scope |
| :---- | :---- |
| External reporting and disclosure obligations | Client engagement confidentiality (CEF) |
| Four disclosure tiers (T-PB, T-SH, T-RG, T-DS) | IP licensing terms (ILTP) |
| Annual Institutional Report (AIR) | Business strategy or marketing |
| Quarterly Operational Update (QOU) | Operational efficiency |
| Event-triggered reporting | Technical delivery execution |
| Contestation interface (CEN-1 to CEN-7) | Internal operational reporting |

### Governing Relationships

| Instrument | Relationship to ERDP |
| :---- | :---- |
| **ICC-8** | Constitutional parent — I6 Transparency Gradient, I8 External Legibility |
| **CEN-1 to CEN-7** | Contestation Interface Standard — ERDP operationalizes CEN requirements |
| **IMP** | Disclosure Records logged as GAO, DRO, OEO, XOO |
| **AICA-5** | Measurement Framework feeds ERDP reporting |
| **ILTP** | IP Register status feeds ERDP reporting |
| **CGF** | Public Designation Register feeds ERDP reporting |
| **HAN/HOF** | HAN authorizes disclosures |
| **DEP** | ERDP amendments require DEP process |

## SECTION 2: DISCLOSURE TIERS

| Tier | Code | Audience | Content Scope | Examples |
| :---- | :---- | :---- | :---- | :---- |
| **Public** | T-PB | General public, open access | Institutional existence, framework doctrine layer, designation register status, annual summary | Framework names, designation register, institutional structure |
| **Stakeholder** | T-SH | Designation holders, engagement counterparties, ecosystem contacts | Operational updates, framework version changes, certification program updates, engagement-relevant disclosures | Framework version changes, program updates, engagement-relevant disclosures |
| **Regulator** | T-RG | Philippine regulatory bodies, operating jurisdiction regulators | Governance structure, accountability architecture, compliance-relevant institutional actions | Governance structure, HAN identification, compliance actions |
| **DFI/Sovereign** | T-DS | ADB, IFC, AIIB, sovereign bodies, ASEAN regulatory counterparties | Full institutional governance package, framework stack architecture, certification standing, financial structure summary | Full governance package, framework stack, certification standing |

### Tier Assignment Rules

| Rule | Description |
| :---- | :---- |
| **Tier Assignment at Preparation** | Every disclosure item carries a tier assignment at the point of preparation. |
| **Disclosure Depth Standard** | T-PB: Doctrine-layer information only; T-SH: Operational updates; T-RG: Governance structure; T-DS: Full governance package. |
| **Tier Elevation** | Reclassification to a higher tier requires HAN authorization. |
| **No Down-Tiering** | Information may be elevated to a higher tier but may not be down-tiered without HAN authorization. |

### Disclosure Depth Standard

| Tier | Content Scope | Prohibited Content |
| :---- | :---- | :---- |
| **T-PB** | Institutional existence, framework doctrine layer, designation register status, annual summary | Operational specifications, invariant formalism, implementation logic, assessment criteria, client-specific information |
| **T-SH** | Operational updates, framework version changes, certification program updates, engagement-relevant disclosures | Internal operational data, financial structure detail, client-specific information |
| **T-RG** | Governance structure, accountability architecture, compliance-relevant institutional actions | Internal operational data, client-specific information |
| **T-DS** | Full institutional governance package, framework stack architecture, certification standing, financial structure summary | Board deliberation content, privileged communications, client-specific information |

## SECTION 3: REPORTING SCHEDULE

### 3.1 Periodic Reporting

#### Annual Institutional Report (AIR)

| Aspect | Description |
| :---- | :---- |
| **Cadence** | Annually, within 90 days of 19 Integrated's operational year close |
| **Audience** | All four tiers (tier-specific versions) |
| **Content** | See Section 4 |
| **Authorization** | HAN confirmation required before publication |
| **Distribution** | Defined distribution list per tier, logged in disclosure record |

#### Quarterly Operational Update (QOU)

| Aspect | Description |
| :---- | :---- |
| **Cadence** | Quarterly, within 30 days of quarter close |
| **Audience** | T-SH and T-DS tiers |
| **Content** | Framework version status, certification program activity summary, engagement pipeline summary (no client-specific information), IP Register material changes |
| **Authorization** | HAN confirmation required before distribution |
| **Distribution** | Active stakeholder and DFI/sovereign counterparty list |

### 3.2 Event-Triggered Reporting

| Event | Disclosure Window | Minimum Tier | Description |
| :---- | :---- | :---- | :---- |
| Material framework version change | 30 days from HAN version confirmation | T-SH | Framework version changes that materially affect governance |
| New designation launch (Active status) | 14 days from program launch | T-PB | New certification program launched |
| Designation revocation (aggregate) | Next QOU cycle | T-SH | Aggregate revocation count (no individual identification) |
| New entity or SPV addition to federation | 30 days from charter compilation | T-PB | New entity added to federation |
| MVOS activation (platform outage or workforce unavailability) | 14 days from restoration | T-SH | Minimum Viable Operations State activation |
| Material contestation resolution | 30 days from resolution | T-SH | Resolution of material contestation |
| Sovereign Transfer instrument execution | 30 days from execution | T-DS | Sovereign Transfer instrument executed |
| HoldCo structural change | 30 days from HAN confirmation | T-PB | Material structural change |
| I9 Catastrophic Risk violation | 24 hours from violation | T-RG | I9 violation (immediate escalation) |
| Constitutional Suspension activation | 14 days from activation | T-SH | Constitutional Suspension activated |

## SECTION 4: ANNUAL INSTITUTIONAL REPORT (AIR)

### 4.1 Content Structure

| Section | Title | Content | Tier |
| :---- | :---- | :---- | :---- |
| **1** | Institutional Identity | HoldCo structure, SPV federation, HAN identification, constitutional stack reference (ICC-8 v2.0), AWOF governance model summary | All |
| **2** | Framework Stack Status | IP Register summary, active frameworks, current versions, version changes during reporting period, Dual-Status Classifications, Sovereign Transfer instruments executed | T-SH+ |
| **3** | Certification Activity | Designation Register status, active programs, placeholder programs, designation holder counts by designation class (reference date stated), revalidation events, revocation aggregate count, Public Designation Register reference | All |
| **4** | Engagement Activity Summary | Aggregate engagement activity — counterparty classification distribution, engagement lifecycle stage distribution, retainer count. No client-specific information. | T-SH+ |
| **5** | Governance Events | Material institutional actions during reporting period, contestation proceedings initiated and resolved, MVOS events, structural changes | T-SH+ |
| **6** | Regulatory Correspondence | ICC-8 regulatory crosswalk status, framework alignment with EU AI Act, NIST AI RMF, OECD Principles, and ISO/IEC 42001 as of report reference date | T-RG+ |
| **7** | Forward Governance | Planned framework developments, designation launches, and structural changes anticipated in the next reporting period | All |

### 4.2 AIR Production Rules

| Rule | Description |
| :---- | :---- |
| **Tier-Specific Versions** | AIR is produced in tier-specific versions. The T-DS version is the most complete; each lower tier is a subset. |
| **Reference Date** | All quantitative disclosures carry a reference date. |
| **HAN Authorization** | HAN confirmation required before publication. |
| **IMP Logging** | AIR is logged as GAO in IMP. |
| **Distribution Logging** | Distribution is logged in disclosure record. |

## SECTION 5: SPECIAL DISCLOSURE PROTOCOLS

### 5.1 Contestation Disclosure Rule

| Rule | Description |
| :---- | :---- |
| **Under Contestation Review** | Any material action under active contestation at the time of reporting is disclosed as Under Contestation Review. |
| **Action Description** | The nature of the action is described; findings are withheld pending resolution. |
| **Post-Resolution** | Post-resolution outcome is carried in the subsequent reporting period or as an event-triggered disclosure within 30 days of resolution. |
| **CEN-7 Public Contestation** | Public contestation submissions are disclosed in aggregate (no individual identification). |

### 5.2 Tier Elevation Protocol

| Rule | Description |
| :---- | :---- |
| **Request** | A DFI, regulatory, or sovereign counterparty may request access to a classification tier above their standard entitlement. |
| **Formal Instrument** | Request must specify scope, purpose, and duration of elevated access. |
| **Authorization** | Tier elevation requires HAN authorization. |
| **No Reclassification** | Elevated access does not reclassify the underlying information. |
| **Reversion** | Access reverts to standard tier upon expiry. |
| **IMP Logging** | Tier elevation instruments are logged as audit artifacts under I3. |

### 5.3 Emergency Disclosure Protocol

| Rule | Description |
| :---- | :---- |
| **Trigger** | HAN unavailable and mandatory event-triggered disclosure window at risk of expiry. |
| **Action** | Disclosure is filed as Pending HAN Authorization with event description, timestamp, and unavailability notation. |
| **Timing** | This satisfies the timing requirement. |
| **Full Disclosure** | Full disclosure is completed upon HAN restoration. |
| **IMP Logging** | The Pending filing is logged as an audit artifact under I3. |
| **I9 Emergency Disclosure** | I9 violations require immediate disclosure regardless of HAN availability. |

### 5.4 Post-Publication Correction Protocol

| Rule | Description |
| :---- | :---- |
| **Trigger** | Material error discovered after publication. |
| **Action** | Correction Notice issued to all audiences that received the original report. |
| **Correction Content** | Correction clearly identified and dated. |
| **IMP Logging** | Correction Notice is logged as an audit artifact. |
| **Archival** | Original report is archived in the IP Register with a correction flag. |
| **DFI/Sovereign Notification** | Corrections to T-DS disclosures require direct counterparty notification. |

### 5.5 Jurisdictional Scope Rule

| Rule | Description |
| :---- | :---- |
| **Mandatory Disclosure** | Mandatory disclosure obligations apply within 19 Integrated's defined operating jurisdictions. |
| **Extra-Jurisdictional Requests** | Extra-jurisdictional regulatory requests are treated as voluntary disclosure requests. |
| **Handling** | Handled through the Tier Elevation Protocol. |
| **HAN Determination** | HAN determines whether voluntary disclosure serves institutional interests. |
| **No Mandatory Obligation** | No mandatory disclosure obligation exists outside defined operating jurisdictions. |

### 5.6 Data Reconciliation Rule

| Rule | Description |
| :---- | :---- |
| **Reference Date** | All quantitative disclosures referencing data maintained in other instruments carry a reference date. |
| **Governing Figure** | The reference date governs the figure disclosed. |
| **Discrepancy Resolution** | Discrepancies between a report figure and a live register are resolved by reference to the stated reference date. |
| **Instrument Sources** | Public Designation Register, IP Register, Engagement Records |

### 5.7 I9 Catastrophic Risk Disclosure Protocol

| Rule | Description |
| :---- | :---- |
| **Immediate Disclosure** | I9 violations trigger immediate event-triggered disclosure. |
| **Timeline** | Disclosure within 24 hours of violation. |
| **Audience** | T-RG and T-DS tiers; T-SH notification. |
| **Content** | Nature of violation, containment status, HAN escalation, system shutdown status (if applicable). |
| **Follow-Up** | Post-incident review disclosure within 60 days. |
| **No Delay for HAN Unavailability** | Emergency Disclosure Protocol applies immediately. |

## SECTION 9: ERDP AND CEN-1 TO CEN-7

| CEN | Requirement | ERDP Implementation |
| :---- | :---- | :---- |
| **CEN-1: Interpretability** | Actions describable to external parties without internal access | AIR and QOU use plain language; external interpretation path maintained |
| **CEN-2: Accessibility** | Defined pathway for external parties to raise objections | Contestation Disclosure Rule; Tier Elevation Protocol; Public Designation Register |
| **CEN-3: Traceability** | Connects to audit chain; contestation triggers reconstructability review | Disclosure Records logged in IMP; traceable to I3 audit chain |
| **CEN-4: Confidentiality** | Restricted information handled by independent review node | T-RG and T-DS tiers; I6 confidentiality protections |
| **CEN-5: Independence** | Originating authority cannot hold voting/blocking rights in contestation | HAN authorizes but does not control independent review |
| **CEN-6: Redress and Remediation** | Corrective actions require I7 continuity impact assessment | Post-Publication Correction Protocol; Correction Notice |
| **CEN-7: Public Contestation** | Any individual may submit a governance concern | Public contestation logged as OEO; 30-day response window; HAN escalation |
