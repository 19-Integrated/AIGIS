# CAD-7 v2.0 — Coalition Accountability Declaration

**Status:** Built — v2.0 (Reconciliation with CDT-7, CTAM, AWOF, AICA-5, ICC-8, RGI-8, CFL-F, and HAN/HOF)  
**Type:** Operational Governance Instrument  
**Parent Stack:** AIGIS Governance Stack  
**Version:** 2.0 — Supersedes CAD-7 v1.0

## PREAMBLE

The Coalition Accountability Declaration (CAD-7) governs multi-agent coalitions as accountable units. It answers: *When multiple individually-authorized agents compose — through delegation, negotiation, or joint task execution — into a coalition that becomes the actual decision-maker, who is accountable, and under what boundary?*

Individual authorization does not transitively confer coalition legitimacy — the same way a set of valid employment contracts does not itself constitute a company. A company is legitimate because an entity-level charter declares it an accountable unit, separate from and prior to its members. Multi-agent coalitions are missing that second layer. CAD-7 is that layer — deliberately lighter than a full ICC-8 charter, since a coalition can form and dissolve inside a single task.

**The core insight:** A coalition of individually authorized agents is not itself authorized unless the coalition is declared as an accountable unit. CAD-7 provides the lightweight accountability declaration that makes multi-agent collaboration governable — with a named Principal, a declared Composability Boundary, and a defined dissolution rule.

## SECTION 1: PURPOSE AND SCOPE

### Purpose

CAD-7 ensures that:

1. **Coalitions are declared** — Multi-agent coalitions are declared before acting  
2. **Accountability is assigned** — A named human Principal is declared before the coalition acts  
3. **Boundaries are defined** — Composability Boundary defines what the coalition is jointly authorized to produce  
4. **Dissolution is defined** — Accountability lapses are defined and re-declaration is required on membership change  
5. **Traceability is maintained** — Coalition actions are reconstructable  
6. **Cross-entity coordination is governed** — Cross-entity coalitions follow defined rules

### Scope

| In Scope | Out of Scope |
| :---- | :---- |
| Multi-agent coalitions (joint decisions, authority delegation) | Individual agent authorization (CDT-7/CTAM) |
| Coalition Principal declaration | Individual agent runtime behavior (RGI-8) |
| Composability Boundary declaration | Full institutional charter compilation (CFL-G/CFL-V) |
| Coalition dissolution and reconstitution | Human authority (HAN/HOF) |
| Cross-entity coalition governance | Technical enforcement (ADTEP) |
| Reconstructability requirement | Institutional memory (IMP) |

### Governing Relationships

| Instrument | Relationship to CAD-7 |
| :---- | :---- |
| **CDT-7/CTAM** | Authorizes individual agents; CAD-7 governs coalitions of authorized agents |
| **RGI-8** | Runtime interpretation of individual boundaries; CAD-7 governs coalition boundaries |
| **AWOF** | Agent classification; CAD-7 coalitions are composed of AWOF-classified agents |
| **AICA-5** | Accountability doctrine; CAD-7 preserves I1 (human remains accountable) |
| **ICC-8** | Constitutional ceiling; CAD-7 may not violate ICC-8 invariants |
| **CFL-F** | Federation logic; CAD-7 defers to CFL-F for cross-entity coordination |
| **HAN/HOF** | Human Principal is the accountability anchor; CAD-7 preserves HAN accountability |

## SECTION 2: COALITION TRIGGER DEFINITION

### Statement

CAD-7 activates only above a threshold: a joint decision produced by multiple agents, or an authority delegation from one agent to another. Ordinary information exchange between agents does not trigger it.

### Requirements

| Requirement | Description |
| :---- | :---- |
| **Joint Decision** | Multiple agents jointly produce a decision |
| **Authority Delegation** | One agent delegates authority to another agent |
| **Threshold** | CAD-7 activates above the threshold |
| **Information Exchange** | Ordinary information exchange does not trigger CAD-7 |

### Trigger Types

| Type | Description | Example |
| :---- | :---- | :---- |
| **Joint Decision** | Multiple agents jointly produce a decision | Research agent and drafting agent jointly produce a compliance report |
| **Authority Delegation** | One agent delegates authority to another | Orchestrator agent delegates a task to a specialist agent |
| **Coalition Execution** | Multiple agents execute a joint workflow | Multiple agents execute a multi-step workflow |

### Non-Triggers

| Type | Description | Example |
| :---- | :---- | :---- |
| **Information Exchange** | Agents share information without joint decision | Research agent shares findings with drafting agent |
| **Routine Communication** | Agents communicate without delegation | Agents coordinate on routine tasks |

### Trigger Detection

| Aspect | Implementation |
| :---- | :---- |
| **Delegation Log** | CAD-7 monitors Delegation Log for authority delegation events |
| **Workflow Orchestration** | CAD-7 monitors workflow orchestration for joint execution |
| **RGI-8 Fidelity Trace** | CAD-7 monitors RGI-8 trace for coalition activity |
| **F-OV Oversight** | F-OV agents monitor for emergent coalition behavior |

## SECTION 4: COMPOSABILITY BOUNDARY

### Statement

What the coalition is jointly authorized to produce, stated separately from the union of members' individual CDT-7/CTAM grants — composition is not additive. This boundary behaves as a Gate: joint activity exceeding it requires a new declaration event, not silent expansion.

### Requirements

| Requirement | Description |
| :---- | :---- |
| **Separate Declaration** | Boundary is separate from members' individual grants |
| **Not Additive** | Composition is not additive |
| **Gate Behavior** | Boundary behaves as a Gate; exceeding requires new declaration |
| **No Silent Expansion** | No silent expansion beyond declared boundary |

## SECTION 5: DISSOLUTION AND RECONSTITUTION RULE

### Statement

Defines when declared accountability lapses (task completion, timeout, explicit end) and requires re-declaration on membership change. An agent leaving mid-task is itself a trigger for re-declaration, not something the coalition quietly absorbs.

### Requirements

| Requirement | Description |
| :---- | :---- |
| **Dissolution Triggers** | Task completion, timeout, explicit end |
| **Membership Change** | Agent leaving mid-task triggers re-declaration |
| **Re-declaration Required** | Membership change requires new declaration |
| **No Quiet Absorption** | Agent leaving is not quietly absorbed |

### Implementation

| Aspect | Implementation |

| **Dissolution on Completion** | Coalition dissolves on task completion |
| **Dissolution on Timeout** | Coalition dissolves on timeout |
| **Dissolution on Explicit End** | Coalition dissolves on explicit end |

## SECTION 7: CROSS-ENTITY COALITION CLAUSE

### Statement

When coalition members span different SPVs, this component determines whether CFL-F's Cross-Entity Coordination Clause is triggered at all, and if so, defers to it entirely without reinterpreting it.

### Cases

| Case | Description | Application |
| :---- | :---- | :---- |
| **Case 1** | Same federation, different SPVs, same HAN | Most intra-federation coalitions do not trigger CFL-F; proceed under CAD-7 Component 2 (shared HAN) |
| **Case 2** | Same federation, different HANs | Fails closed (currently inapplicable — single HAN) |
| **Case 3** | Different federations | Fails closed at the federation level (CFL-F) |

### Case 1 Details

| Aspect | Description |
| :---- | :---- |
| **Threshold** | CFL-F requires HoldCo acknowledgment only when an action "directly implicates the function of another SPV" |
| **High Bar** | High bar concerning mandate, resources, or structural role, not ordinary cross-functional collaboration |
| **Most Coalitions** | Most intra-federation coalitions do not meet this threshold |
| **Action** | Proceed under CAD-7 Component 2 Principal Declaration (shared HAN) |

### Case 1 Exception

| Aspect | Description |
| :---- | :---- |
| **Function Implication** | If a specific coalition's output crosses the function-implication threshold |
| **CFL-F Applies** | CFL-F clause applies in full |
| **HoldCo Acknowledgment** | Genuine per-instance HoldCo acknowledgment required before execution |
| **No Shortcut** | CAD-7 does not shorten this |

### Case 2 and Case 3

| Case | Description | Action |
| :---- | :---- | :---- |
| **Case 2** | Same federation, different HANs | Fails closed. Different HANs \= different accountability anchors. Coalition cannot proceed. |
| **Case 3** | Different federations | Fails closed at the federation level. Different charters, HANs, ICC-8 interpretations. |

### Cross-Entity Rules

| Rule | Description |
| :---- | :---- |
| **CFL-F Threshold** | CFL-F applies only when action implicates another SPV's function |
| **Most Coalitions** | Most intra-federation coalitions do not trigger CFL-F |
| **Full Application** | When CFL-F applies, it applies in full |
| **No Reinterpretation** | CAD-7 does not reinterpret CFL-F |
| **Case 2** | Different HANs → fails closed |
| **Case 3** | Different federations → fails closed |

## SECTION 8: RECONSTRUCTABILITY REQUIREMENT

### Statement

After any coalition-level incident: who declared the coalition's Principal, under what Composability Boundary, and when. If the trace mechanism is unavailable, the coalition's joint capability fails closed — individual agents continue under their own grants, but collective decision-making halts until trace is restored.

### Requirements

| Requirement | Description |
| :---- | :---- |
| **Trace Required** | Who declared Principal, under what Boundary, and when |
| **Trace Unavailability** | If trace unavailable, coalition fails closed |
| **Individual Continuation** | Individual agents continue under their own grants |
| **Collective Halt** | Collective decision-making halts until trace restored |

### Implementation

| Aspect | Implementation |
| :---- | :---- |
| **Trace Logging** | All coalition declarations logged in IMP |
| **Trace Availability** | Trace must be available for reconstruction |
| **Fail Closed** | Coalition fails closed if trace unavailable |
| **Restoration** | Collective decision-making resumes when trace restored |

### Reconstructability Flow

Coalition Incident  
  │  
  ├──→ Trace Available → Reconstruct  
  │       │  
  │       └──→ Accountable  
  │  
  └──→ Trace Unavailable → Coalition Fails Closed  
          │  
          ├──→ Individual Agents Continue  
          ├──→ Collective Decision-Making Halts  
          └──→ Trace Restored → Resume Collective Decision-Making

### Reconstructability Rules

| Rule | Description |
| :---- | :---- |
| **Trace Required** | Who declared Principal, under what Boundary, and when |
| **Fail Closed** | Coalition fails closed if trace unavailable |
| **Individual Continuation** | Individual agents continue under their own grants |
| **Collective Halt** | Collective decision-making halts until trace restored |
| **Restoration** | Resume when trace restored |
